## 📝 학습 내용

---
### 문자열 계산기에서 배운 것
- TDD 방식 개발 (Red-Green-Refactor)
- 메서드 분리를 통한 단일 책임 원칙
- Early Return 패턴으로 else 제거
- Enum을 활용한 에러 메시지 관리
- 작은 단위의 의미 있는 커밋
---
### 자동차 경주에서 배운 것
- 일급 컬렉션 패턴 적용
- 객체에 메시지 보내기
- 레이어 구조 (Domain, View, Controller)
- 의존성 주입으로 유연한 설계
- 책임 분리와 캡슐화
- try-catch로 예외 처리
---
### 로또에서 배운 것
- Enum 활용한 등수 관리와 상금 계산
- 일급 컬렉션 (Lottos)으로 객체 관리
- Domain 중심 설계 (비즈니스 로직 분리)
- Generator 패턴으로 객체 생성 분리
- 상수 통합 관리 (DRY 원칙)
---
### 요트 다이스에서 배우 것 
- Dice를 값 객체로 만들어서 불변성 유지하기
- Dices를 일급 컬렉션으로 관리하고, Enum으로 카테고리 전략 패턴 구현
- ScoreBoard로 게임 상태 관리하면서 MVC 패턴 적용
- Full House는 플래그 변수로 3개+2개 판별, Four of a Kind는 1~6 완전 탐색
- Straight는 연속 패턴 매칭으로 구현
- List.set()으로 선택한 주사위만 재굴림하고, 사용자 번호(1~5)를 배열 인덱스(0~4)로 변환
- split()과 trim()으로 "1,3,5" 형태 파싱, while(true) + try-catch로 재입력 처리
- 빈 값 → 형식 → 범위 → 중복 순서로 검증하고, Set으로 중복 체크
- while + break로 최대 2번 재굴림 구현, 조건 충족 시 Early Return
- 한 메서드는 한 가지 일만, hasValue() 같은 헬퍼 메서드 활용
- 매직 넘버는 상수로, 메서드 이름으로 의도 표현, DRY 원칙 지키기
- 빈 리스트로 취소 신호, boolean으로 실행 여부 전달
